# 视觉层 skill —— 从 P3 与明日方舟提炼，并针对本项目已犯过的错

这份文档是**动手前必读**。它由两部分组成：从两款游戏提炼出的设计法则，以及本项目
真实踩过的坑（每一条都有对应的自动检查，防止再犯）。

---

## 一、提炼：两套语言，各自负责什么

### Persona 3（P3）—— 负责「版面张力」

| 法则 | 做法 |
|---|---|
| 高对比排版 | 巨大无衬线标题 + 极紧字距 + 斜切（skew），标题就是主视觉 |
| 硬投影贴纸字 | `text-shadow: 3px 3px 0 主色, 7px 7px 0 黑` 双层错位 |
| 半调网点 | `radial-gradient` 点阵，铺在色带上、边缘用 mask 淡出 |
| 速度线 | `repeating-linear-gradient` 斜向细线，透明度 ≤ 0.12 |
| 巨大衬底数字 | 描边空心字压在区块标题后，`-webkit-text-stroke` |
| 暗时母题 | 一个**具体时刻**作为情绪锚点（本项目：19:59） |
| 碎裂边缘 | `clip-path` 折线切口，让区块不落在直线上 |

### 明日方舟 / 罗德岛终端 —— 负责「仪表可信度」

| 法则 | 做法 | 出处 |
|---|---|---|
| 凯尔希主色 | **骨白 + 医疗绿**（`#f4f1e8` / `#b6d94a`） | 皮肤素材表 |
| 两套字体寄存器 | 古典标题用**衬线大写**；仪表标签用**等宽／窄体大写宽字距** | UI/UX 拆解 |
| 双语装饰 | 每个标签配第二语言小字（`主页 HOME`） | UI/UX 拆解 |
| 骨白印张贴在暗场 | 浅色面板 + 2px 黑框 + 45° 切角 | 同上 |
| 网点纸 + 警戒条纹 | 散点点阵；粗斜条纹（绿/黑）做分隔条 | 同上 |
| 暗角 vignette | 页面四周压暗，视线收到中心 | 同上 |
| 局部马赛克化 | 红青双色错位，**只用于强调**，不做底纹 | 同上 |
| 页边装帧 | 套准标记、标尺刻度、直角走线、刻度弧 | 仪表语言通用 |

**分工原则：P3 管"版面有多冲"，方舟管"它看起来是不是一台真仪表"。两者都不许碰正文可读性。**

## 二、本项目已犯过的错（动手前逐条自问）

| # | 犯过的错 | 后果 | 现在的规矩 |
|---|---|---|---|
| 1 | 缓存号加了但**内容变了不升号** | 我报"已上线"，你屏幕上纹丝不动 | 每次改 CSS／图片，**必须同时升 `?v=`**，并核对线上内容 |
| 2 | 覆盖站内 `color: transparent` 却没补填充 | **所有页面标题消失** | 关渐变必须同时给显式 `color` + `-webkit-text-fill-color` |
| 3 | 浅色面板上放浅色标题 | **白底白字**（CTA 区） | 浅色面板内**所有**后代文字（含 h1/h2/h3/按钮/链接）强制深色 |
| 4 | 把插画（撕裂文档＋大 X）当正文衬底 | 叉子横穿段落 | **任何装饰不得进入正文栏**；装饰只在页边 |
| 5 | 固定定位元素互相压住 | 播放器胶囊压住作战计时 | 四个角各一个固定元素，**互不重叠**，逐个核对 |
| 6 | 只渲染一张截图就报完成 | 你逐页发现自己发现问题 | **逐页截图 + 自动审计**通过后才报告 |
| 7 | 动效不管用户偏好 | — | 所有动画必须在 `prefers-reduced-motion` 下停止 |
| 8 | 只改 `color`，没改 `-webkit-text-fill-color` | 算出来的对比度是对的，屏幕上却是白字（`.tag` 卡在 **1.69:1**） | **真正画字的是填充色**：任何改文字颜色的规则都要**同时**写 `-webkit-text-fill-color`；带底色的胶囊（`.tag` / `.badge`）必须把**底色与字色成对**写在一起，不能只声明一半 |
| 9 | 后面的样式表用 `!important` 改了同一对颜色里的**一个**属性 | 底色来自 style.css、字色来自 rhodes.css，两者各自都"正确"，合起来不可读 | 加载顺序是 `style.css → p3.css → hud.css → rhodes.css`，**最后加载的那层说了算**；跨层覆盖一对颜色时必须整对重写，并核对最终计算值 |
| 10 | 升缓存戳时用 PowerShell 的 `Get-Content -Raw` + `WriteAllText` 把整个 HTML 往返了一遍 | UTF-8 被当成 ANSI 转码：中文和符号全成乱码，而且 GBK 双字节序列**会吞掉紧跟其后的 ASCII**（`◈<` 里的 `<` 就这么没了），404／join／register 的内联脚本直接语法错误 | 改静态文件一律走 `node tools/bump-asset-stamp.mjs`：强制 UTF-8 解码、写回前逐个核对非 ASCII 码点没变，任何一条不过就拒写 |
| 11 | 对比度审计**只量了当时的主题**（实际上永远是 dark） | 浅色主题从来没被检查过：`.eyebrow` 3.66:1、导航链接 2.9:1、music.html 整页深底深字 1.01:1 —— 一路绿灯地错着 | 两种主题**各量一遍**，行名带主题名 |
| 12 | 暗角 `html::before` 写了 `z-index: 2`，而正文没有 z-index | 这层 0.72 的黑**压在文字上面**：手机视口下一块骨白印张实测只剩四成亮度，深墨字掉到 2:1 | 装饰性叠加层必须在内容之下；给 `main` 一个高于它的 `z-index`。这类错**只有量真实像素才看得见** |
| 13 | 页面自带深色面板，却让会随主题翻档的样式表决定字色 | music.html 的 `.ms-right` / 歌词抽屉在两种主题下都是深色，而 `rhodes.css` 在浅色主题里把 h1/h2 改成深墨 → 深底深字，整页读不了 | 自成一体的深色面板要**自己钉住字色**，规则带 `html[data-theme]` 前缀压过全局层；站头若压在深色画面上，也一样处理 |

## 三、自动审计（`tools/browser-check.mjs` 的 `审计:` 段落）

产出前必须跑通，任何一条失败都算未完成：

1. **对比度**：遍历可见文字，按 **WCAG AA** 判定（正文 4.5:1，≥24px 或 ≥18.66px 粗体 3:1）。
   失败时逐条打印**实际颜色**与**提供背景的祖先元素**——前景用的是 `color` 还是
   `-webkit-text-fill-color`、底色是什么、由哪个属性提供、来自哪个元素的哪个 class。
   页面无论通过与否，都另外打印"最紧的三处"，这样绿色的一次运行里也看得到真实色值。
   —— 直接拦住"白底白字"这类错误，并且**指出真凶而不是只给一个 ratio**。
   半透明底色会**按 alpha 逐层合成**后再算，不是只看色值：`rgba(182,224,74,.14)`
   压在近黑页底上合成出来是 `rgb(32,39,17)`（约 12:1），早期版本把它读成亮柠檬绿，
   于是误报 1.18:1。海报层大量使用这类薄涂层，所以这条必须先对。
2. **正文栏洁净**：把正文容器的包围盒与固定装饰层比对，装饰不得覆盖内容列。
3. **固定元素不重叠**：四个角的固定块两两求交，有交集即失败。
4. **标题可见**：每个 `h1/h2` 的计算填充不得为透明、尺寸不得为 0。
5. **缓存戳一致**：页面里所有 `?v=` 必须等于当前戳。
6. **实测像素对比度**：每个视口取几个滚动位置截屏，把每个文字元素矩形内的像素取出来，
   剔除接近字色的像素（那些是字），取剩下像素的中位亮度当**真实的底**，再算一次对比度。
   —— 沿祖先链找底色的模型对这个站根本不成立：正文底下压着一张固定定位的照片，
   它不是文字的祖先，祖先链一路走到 body 的骨白底，于是算出 16:1 而屏幕上只有 1.3:1。
   照片、canvas、任何"不是祖先画的底"，只有量像素才骗不过去。
   量之前要先把动画停掉（`.reveal` 淡入中被拍到半透明会误判）、把 `scroll-behavior`
   改成 `auto`（平滑滚动会让"取矩形"和"截图"落在两个位置上），手机模拟下还要按
   `截图尺寸 / 布局视口` 换算坐标。

> 整个 `审计:` 段落跑在**每一页**上，而且**两种主题各跑一遍**。它曾经嵌在
> 「本页无唱片播放器」的 else 分支里、也只量当时的主题，于是唱片页（全站正文最多
> 的一页）连一次对比度检查都没有、浅色主题从来没被看过——绿色的运行其实是假的。
> 闸门悄悄跳过一页，比没有闸门更坏。

## 四、产出流程

1. 先跑第 3 节的审计，**带着失败项开工**（先复现问题）
2. 改完再跑审计，全绿：`node tools/browser-check.mjs 全部`
3. 逐页截图，人眼过一遍深浅两种主题：
   `node tools/shot.mjs poster.html preview/poster-dark.png dark`
   （第 7 个参数写 `viewport` 就只抓首屏——核对固定控件有没有压住正文时要用它，
   整页截图会把 `position: fixed` 的元素画在首屏位置，看着像压住了，其实是截图假象）
4. 升版本戳：`node tools/bump-asset-stamp.mjs <新戳>`，先加 `--dry` 看一眼
5. 推送后**抓线上**复验审计与截图，最后才报告

## 六、官方小人（Spine）怎么变成站内的一张图

游戏里的「战斗小人」没有现成的平面图，只有 Spine 模型。做法是**渲一次、只留一张 PNG**，
站点本身不带运行时、也不联网 —— 和站内其它立绘待遇相同。

1. 模型：`isHarryh/Ark-Models` 的 `models/<编号>_<代号>/`，里面是
   `build_char_XXXX_<代号>.{skel,atlas,png}` 三个文件（缪尔赛思是 `249_mlyss`）。
2. 运行时：`.skel` 头部就是版本号（缪尔赛思是 **3.8.99**），要拿**对应大版本**的
   `spine-webgl.js`（`EsotericSoftware/spine-runtimes` 的 `3.8` 分支）。版本对不上会直接报错。
3. 渲染页：`file://` 下 `AssetManager` 读不了资源，浏览器要用
   `--allow-file-access-from-files` 启动；WebGL 在无头里要 `--enable-unsafe-swiftshader`。
4. **取景要自己量**：`SkeletonData` 上的 `width/height` 是给攻击／技能动画横向伸展留的
   画布（缪尔赛思是 686×402），直接拿它取景，人只有巴掌大；而 3.8 的 `SkeletonBounds`
   在这份模型上量不出东西（`minX` 恒为 NaN）。可靠的办法是遍历 `skel.slots`，
   对每个 `attachment` 调 `computeWorldVertices`，自己求包围盒
   （region 用 `att.offset.length` = 8，mesh 用 `att.worldVerticesLength`）。
5. **透明背景**：`Page.captureScreenshot` 默认把页面合成到白底，导出的 PNG 会是
   `24bppRgb`、透明通道没了。截图前先
   `Emulation.setDefaultBackgroundColorOverride({color:{r:0,g:0,b:0,a:0}})`，
   拿到的才是 `32bppArgb`。
6. 画布宽高比取 3:4，和立绘台一致，切过去时不会有留白跳变。
7. 渲出来的 PNG 同样是**第三方素材**：进 `.gitignore`，不进仓库。

> 这一整套只在**本地**跑一次，`spine-webgl.js` 与 `.skel/.atlas/.png` 都不入库；
> 仓库里只多一张自己渲的成品图（而且那张也不入库），页面依旧是零依赖静态站。

## 五、海报层（`assets/css/poster.css` + `poster.html`）

按方舟直播的三张参考做的版式试验。这一层**只由 `poster.html` 加载**，其余 14 个页面不受影响。

| 参考 | 借来的东西 |
|---|---|
| `ref_disc` | 切片式同心仪表盘：细辐射刻度、扇形缺口、同心导引环、柠檬绿标记点 |
| `ref_gate` | 层叠告示板、四角套准框、双语微标签、超大斜切标题、十字套准、半调网点 |
| `ref_tunnel` | 一圈圈退向中心的同心环，外加四周压暗的暗角 |

**参考图里最诱人、也最危险的手法，就是半透明玻璃板压浅色字** —— 那正是上一版被审计
拦下的原因，实测只有 1.1～1.7:1。这里保留的是**层叠结构**（顺序、错位、角标、微标签），
丢掉的是玻璃：

- 承载文字的板一律**不透明**，底色与字色成对声明在**同一条规则**里；
  成对的值收在 `--po-*` 令牌，深浅两套主题各一对，配对关系不变、只换档位。
- 半透明只留给**不承载文字**的装饰层：网格、网点、同心环、辐射线、套准标记。
- 板内覆盖别层样式时**带 `html[data-theme]` 前缀**。`rhodes.css` 里的
  `html[data-theme="light"] h1, h2 { … !important }` 特异度是 (0,1,2)，只写
  `.po-board h1` 的 (0,1,1) 压不住它，标题会在浅色主题下被换成另一档骨白。
- 板内**不写 `*`**：通配会把那些自带底色的胶囊一起吃掉，它们的字色必须由各自的
  成对规则决定，不能被一锅端。
- 透明的幽灵按钮，字色必须跟着**身后那块真正的底**走；写成「场上的字色」就会在
  深色主题里变成浅字压浅板（审计实测 1.00:1）。
